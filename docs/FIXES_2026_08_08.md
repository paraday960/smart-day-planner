## جزئیات فنی مهم

### C1 — workflow release حالا fail-on-error است
حذف `|| echo "..."` از مراحل Analyze و Tests. خطای analyze یا تست = توقف workflow.
(نکته: CI قبلاً هم با تست‌های پاس‌شده سبز بود؛ این اصلاح برای آینده است که هیچ
شکستی نادیده گرفته نشود.)

### C2 — امضای release فقط با کلید واقعی
- در `build.gradle.kts`، fallback به کلید debug حذف شد.
- task `preReleaseBuild` اگر `android/key.properties` نباشد، build را با پیام
  واضح متوقف می‌کند (build های debug تحت تأثیر نیستند).
- workflow release جدید مرحلهٔ «Setup release signing» دارد که keystore را از
  GitHub Secrets می‌سازد. **برای اولین release باید این ۴ سکرت تنظیم شوند:**
  `KEYSTORE_BASE64`، `KEYSTORE_PASSWORD`، `KEY_ALIAS`، `KEY_PASSWORD`.
  (ساخت keystore: `keytool -genkey -v -keystore smart-day-planner.jks -keyalg RSA -keysize 2048 -validity 10000 -alias smartday`)

### H2 — استارتاپ ضدخطا + crash log
- `main()` حالا داخل `runZonedGuarded` اجرا می‌شود.
- `FlutterError.onError` و `PlatformDispatcher.instance.onError` خطاها را در
  `<اسناد>/error_log.txt` ثبت می‌کنند.
- هر بارگذاری (repository/سرویس) جداگانه try/catch شده؛ خرابی یکی = بقیهٔ اپ سالم.

### H3 — workflow Offline Capabilities ساخته شد
`docs/OFFLINE_CAPABILITIES_WORKFLOW.md` از قبل محتوای دقیق را داشت ولی فایل در
ریپو نبود (توکن قبلی مجوز workflows نداشت). فایل ساخته شد (بدون مرحلهٔ پچ
بلااستفادهٔ desugaring). حالا README درست است: تب Actions → **Offline Capabilities
Build** → Run workflow.

### H4 — تست بازتولید برگشت (و دیگر timeout نمی‌شود)
علت timeout قبلی: عملیات واقعی sqflite در محیط fake-async تست‌های widget هرگز
کامل نمی‌شد. راه‌حل: اجرای عملیات دیتابیس داخل `tester.runAsync` + شمارش بدون
وابستگی به فریم (`rawCount`). تست در ~۳.۵ ثانیه پاس می‌شود.

### M2 — شناسهٔ اعلان پایدار
- task ها: رجیستری `taskId → notificationId` در SharedPreferences (شمارندهٔ
  ماندگار از ۱۰۰۰) — هیچ برخوردی ممکن نیست و بعد از cancel، id آزاد می‌شود.
- هشدارهای هوشمند: شمارندهٔ ماندگار در prefs (قبلاً بعد از هر ری‌استارت از صفر
  شروع می‌شد و اعلان قبلی را بازنویسی می‌کرد).

### M5 — کلید AI در حافظهٔ امن
`flutter_secure_storage` (Keystore/Keychain) با fallback خودکار به
SharedPreferences در تست/دستگاه‌های بدون Keystore + مهاجرت خودکار کلید قدیمی.
دستور `flutter pub get` را بعد از pull اجرا کنید (pubspec.lock به‌روز شده).

### M6 — checksum مدل Piper
SHA-256 مدل `vits-piper-fa_IR-amir-medium.tar.bz2` =
`46af65c1...e84f864` در کد ثبت و بعد از دانلود بررسی می‌شود؛ فایل خراب/دستکاری‌شده
نصب نمی‌شود. باگ prefix مسیر در استخراج tar هم اصلاح شد (`startsWith(dest + '/')`).

### M1 — فیلتر تقویم
عبارت همیشه-درست `!(isReadOnly ?? false) || true` حذف شد؛ رویدادها از همهٔ
تقویم‌ها خوانده می‌شوند (حتی فقط‌خواندنی مثل تعطیلات — عمدی، چون فقط خواندن است).
